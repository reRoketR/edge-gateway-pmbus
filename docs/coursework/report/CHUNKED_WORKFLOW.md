# Chunked Report Workflow

Поточний режим: звіт пишеться невеликими ітераціями, але з підвищеною
деталізацією кожного розділу.

## Правило ітерації (обов'язково)

1. В роботі одночасно тільки один файл секції.
2. Для секції готується завершений змістовий шматок (не ескіз).
3. Для цього шматка закривається quality-gate.
4. Лише після погодження переходимо до наступної секції.

## Глибина опрацювання секції

Для кожного розділу в ітерації обов'язково фіксуємо:

1. Мету та межі розділу.
2. Трасування на код/документацію/схеми (конкретні файли).
3. Готові підписи та місця вставки рисунків/таблиць.
4. Чернеткові посилання `[n]` на джерела.
5. Критерій "готово" саме для цього розділу.

## Порядок секцій

1. `sections/01_technical_assignment.md`
2. `sections/02_introduction.md`
3. `sections/03_section1_functional_scheme.md`
4. `sections/04_section2_architecture.md`
5. `sections/05_section3_software.md`
6. `sections/06_section4_testing.md`
7. `sections/07_conclusions.md`
8. Інтеграція в `coursework_report_draft.md` та експорт в DOCX/PDF

## Quality Gate (для кожної ітерації)

1. Логічно завершений шматок тексту (не лише план).
2. Прямі посилання на релевантні артефакти репозиторію.
3. Позначені/підготовлені рисунки та таблиці для цього розділу.
4. Посилання `[n]` проставлені у всіх ключових твердженнях.
5. Обсяг та стиль відповідають вимогам методички.
